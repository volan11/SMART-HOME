## 19.11.2026. Работа №4. Виртуальные датчики в Node-RED

- **ВМ / компонент:** CTRL-01, IOT-01.
- **Что сделано:** на CTRL-01 в `/root/practice4/ctrl` размещены `receiver.js` и `compose.yml`,
  приёмник запущен через Docker Compose на порту 8080. На IOT-01 в `/root/practice4/iot`
  запущен Node-RED (порт 1880). В Node-RED развёрнут поток из двух датчиков: inject (5 с) →
  change → http request → debug.
- **Результат проверки:** `curl /health` возвращает `{"status":"ok"}`; в журнале приёмника
  видны показания TEMP-01 и HUM-01 с интервалом 5 секунд.
- **Проблема:** консоли ВМ «зависали» из-за того, что проект GNS3 закрывался при отключении
  web-UI (`auto_close=true`). **Решение:** автозакрытие отключено, проект удерживается открытым.

## 19.11.2026. Работа №5. Эмуляция вентилятора

- **ВМ / компонент:** CTRL-01, IOT-01.
- **Что сделано:** приёмник обновлён до версии 2 (появился `/api/actuators`), сохранена
  резервная копия версии 1. В поток добавлены switch (`payload.value > 30`) и два change-узла,
  формирующие команды `ON`/`OFF` с полями `fan.state`, `fan.actuator_id=FAN-01`,
  `fan.zone=server_room`, `fan.mode=auto`, `fan.timestamp`.
- **Результат проверки:** подача 31 → `ON`, 25 → `OFF`, 30 → `OFF`. Команды зафиксированы
  в журнале приёмника с корректными полями.
- **Проблема:** при ручной проверке границы порога легко получить `ON` при 30 °C, если
  использовать `>=`. **Решение:** условие строго `> 30`, проверено тестом 30 → `OFF`.

## 19.11.2026. Работа №6. Интеграция SQLite на DB-01

- **ВМ / компонент:** DB-01, CTRL-01, IOT-01.
- **Что сделано:** в `/root/practice6` размещены файлы сервиса хранения, создана база
  `data/telemetry.sqlite3` по схеме `create_db.sql` (таблицы `measurements` и
  `actuator_events`). Сервис запущен через Docker Compose на порту 8081. В поток Node-RED
  добавлены http request-узлы для параллельной отправки показаний и команд на CTRL-01 и DB-01.

- **Проблема:** в RED OS 8 нет пакета `sqlite3`, а репозиторий колледжа недоступен.
  **Решение:** база создана модулем `sqlite3` из Python 3.11 (`executescript`), проверка
  записей выполнена тем же модулем.

## 19.11.2026. Работа №7. Prometheus и Grafana

- **ВМ / компонент:** MON-01, CTRL-01.
- **Что сделано:** приёмник обновлён до версии 3 с `/metrics`. На MON-01 установлен
  Prometheus 3.16.0 из официального архива, настроен job `office-controller`
  (CTRL-01:8080, `/metrics`, интервал 5 с, таймаут 3 с), проверен `promtool`, оформлен
  systemd-юнит. Установлена Grafana 11.3.0, включён источник `prometheus-office` (UID),
  импортирована выданная панель, через провижининг созданы три правила оповещения
  (TEMP-01, HUM-01 — возраст > 20 с при `up == 1`; CTRL-01 — `up < 1`), интервал оценки
  10 с, Pending 0 с.
- **Результат проверки:** цель `office-controller` — UP; панель показывает температуру,
  влажность, состояние вентилятора и возраст данных; остановка TEMP-01 переводит правило
  TEMP в Alerting (возраст 56 с), остановка HUM-01 — правило HUM (54 с), остановка приёмника —
  правило CTRL (`up=0`), правила датчиков при этом в No data.
- **Проблема 1:** RPM Grafana требует `/sbin/service`, которого нет в RED OS.
  **Решение:** установка `rpm -Uvh --nodeps` (зависимость относится только к SysV-скрипту).
- **Проблема 2:** Prometheus не стартовал из-за прав на `/var/lib/prometheus`.
  **Решение:** `chown -R prometheus:prometheus` на каталоги данных и конфигурации.
- **Проблема 3:** в первом варианте правила «CTRL недоступен» порог был `< 0`, поэтому
  правило не срабатывало при `up=0`. **Решение:** порог изменён на `< 1`, правило проверено.
- **Проблема 4:** SMTP Яндекса сначала отклонял авторизацию с кодом 535
  «user does not have access rights to this service» — в ящике был выключен доступ для
  почтовых программ. После включения доступа письма доставляются: получены сообщения
  [FIRING] и [RESOLVED] по TEMP-01 (14:52 и 14:53) и по HUM-01 (14:54 и 14:56),
  подтверждение — practice7/mail-evidence.txt.
